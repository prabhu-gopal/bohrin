## TL;DR

Bohrin 1.0.0 is a new tool: it audits the **verifier** (the program that decides
whether an RL task was solved), not the model. Point it at a `verifiers` v1
taskset and it submits provably-wrong candidates, records the ones the verifier
accepts, and reports the **Verification Gap** with a copy-pasteable command to
reproduce each finding.

If you installed `bohrin` before this release, read *Upgrade impact* — the
`0.x` line was a different program.

## Upgrade impact

- **Breaking changes:** the `bohrin` name now belongs to this verifier auditor.
  The `0.1.0` / `0.2.0` releases on PyPI were a static analyser for robot
  demonstration data; they are **yanked** and point at
  [`adduct`](https://pypi.org/project/adduct/), which is that tool with its full
  history. The version jumps straight to `1.0.0` so the discontinuity reads as a
  break, not an upgrade.
- **Action required:**
  - If you want the robot-dataset analyser: `pip install adduct`.
  - If you want the verifier auditor: `pip install 'bohrin[verifiers]'` (the
    `verifiers` extra is required to audit anything; it pulls in a large
    dependency tree, so the base install stays small and tells you to add the
    extra rather than failing with an import error).
- **New minimums:** Python **3.11** (was 3.10). Two independent reasons:
  `verifiers` itself requires `>=3.11,<3.14`, and Python 3.10 reaches end of life
  on 31 October 2026.

## Highlights

- **Audit a real taskset in seconds.** Candidates are scored by constructing a
  synthetic trace and invoking the task's reward functions directly — no agent,
  no model inference, no rollout.
- **Two open probes.** `weak_oracle` submits provably-wrong candidates and
  records the ones a verifier accepts; `determinism` submits one identical
  candidate repeatedly and reports disagreement.
- **Every finding carries a reproduction command.** Running it re-runs exactly
  that one finding, against that one task, with that one operator.
- **The Verification Gap always prints with its coverage.** `34 / 100 ·
  coverage: 2 of 2 probes` — a gap from two probes and a gap from six are
  different quantities, and the report never lets them share a bare number.

## Added

- The probe framework and contract, the `weak_oracle` and `determinism` probes,
  the baseline mutation operators, and the `audit` / `list-probes` / `explain`
  command surface.
- **The `verifiers` v1 adapter** — Bohrin can read and score a real taskset.
- **Isolation is classified, enforced and recorded.** Scoring runs the
  taskset's own reward functions, which is arbitrary third-party code. Bohrin
  refuses to execute it with no boundary unless `--unsafe-local` is passed, and
  the level used is written into the report. The level below a container is
  called `subprocess` and described as blast-radius containment, never a
  sandbox.
- **Concurrency adapts to the machine** — derived from core count and free
  memory rather than fixed, so an audit does not crowd out the laptop running
  it. macOS is handled explicitly.
- **`weak_oracle` requires a green baseline.** Where a task ships a reference
  solution it is submitted unchanged first and must pass; without that, an
  accepted mutant cannot be told apart from Bohrin submitting in a form the
  verifier does not understand. Tasks that fail their baseline are excluded from
  the score and reported.
- **`determinism` reports the statistical power of its own measurement.** A null
  result bounds the flake rate rather than proving determinism: at five repeats
  a verifier that flips 5% of the time is missed roughly 77% of the time. The
  headline reads "no variance observed in 5 runs", not "deterministic".

## Known limitations

- A task whose reward function requires a runtime is **refused**, not scored on
  a partial rubric — a partial rubric awards full marks to a submission that
  does nothing.
- The false-positive rate is **unmeasured** until a public sweep measures one.
  The clean-fixture test proves zero false accusations on a fixture we wrote,
  which is a regression guard, not a rate. No accuracy claim is made in the
  meantime. `docs/05_ROBUSTNESS.md` records seven known weaknesses with the
  evidence behind each.

## Verified

- Full lint / format / `mypy --strict` / test matrix across Python 3.11–3.13 on
  ubuntu and macOS, plus an installed-wheel smoke test.
