## TL;DR

Bohrin now reads [Inspect](https://inspect.aisi.org.uk/) evaluations as well as `verifiers`
environments: point it at a file of `@task` functions and every scorer gets the same checks,
without running a model. The repository also says plainly which job is free forever and which
jobs are sold. Nothing to do on upgrade; add the `inspect` extra to audit Inspect tasks.

## Upgrade impact

- **Breaking changes:** none
- **Action required:** none — `pip install --upgrade 'bohrin[verifiers]'`, or
  `pip install 'bohrin[inspect]'` for Inspect support
- **New minimums:** none

## Highlights

- **Audit Inspect evaluations** (#76) — each sample becomes a task and its target the declared
  answer, and each scorer is called directly with the candidate as the model's reply. No solver
  runs and no model is asked anything.
- **Scorers that cannot be graded offline are refused, never guessed at** (#76) — and a scorer
  that reaches for a model or a sandbox mid-grading has that submission declined rather than
  reported as the grader crashing.
- **One complete job is free forever** (#77) — checking a grader you own, on your machine.

## Added

- **The `inspect` adapter.** `pip install 'bohrin[inspect]'`, then `bohrin audit` a file or a
  directory of Inspect `@task` functions. Tasks that build with no arguments are read; one that
  needs arguments, or a dataset that cannot be downloaded, is reported as not loadable rather
  than skipped silently.
- **Refusals before scoring.** A task that runs in a sandbox, the model-graded built-in scorers,
  and `choice` — which grades answers the multiple-choice solver marks — are refused with a named
  reason and never counted as clean.
- **Refusals while scoring.** A custom scorer may call a model for only some replies: an exact
  match first, a judge as the fallback. Every route to a model or a sandbox is intercepted during
  a Bohrin score call, including when the scorer catches the failure itself and returns
  "incorrect".
- **`ScoringRefused`.** An adapter can now decline to score one submission. An audit reports a
  grader as crashing on a submission when other submissions to the same task scored, and that
  inference is only sound if the exception came from the grader. Declined submissions are counted
  as errors and never reported as a defect.

## Changed

- **The boundary is one complete job, not a feature list.** Checking a grader you own, on your
  machine, is free forever and complete: no account, no upload, no check that exists only in a
  paid tier, and never a message saying a finding is withheld. What is sold is different jobs:
  adaptive search, watching a training run, connectors into systems Bohrin does not run, holding a
  risky action at runtime, team history, and certificate issuance.
- **New fixed checks and adapters are accepted again**, including checks that read only what a
  user already has locally. `CONTRIBUTING.md` lists what each must carry: a mechanism sentence,
  public evidence, a test that fails before and passes after with the clean fixture staying clean,
  and a real target it was checked against.
- **The boundary page lists what actually ships:** four probes, nine operators, seventeen answer
  relations, and the `verifiers` and Inspect adapters.
- **Settled decisions are recorded as decisions**, with the reasoning that produced each.

## Fixed

- **A list target no longer produces a false accusation.** An Inspect sample whose target lists
  several valid answers declares no single reference: treating one item as "the" answer makes
  every other valid item look like a wrong answer the grader accepted. Found on real data before
  the adapter merged.

## Known limitations

- Inspect scorers that need a model or a sandbox are refused, not audited. That includes
  model-graded scorers and anything that runs commands in a container.
- The adapter intercepts private upstream functions to keep a scorer from reaching a model. A test
  pins those against `inspect_ai` 0.3.263, so an upstream change fails the build rather than
  silently changing audits.

## Verified

- `ruff check` · `ruff format --check` · `mypy --strict` · `pytest` — all clean, **452 tests**, on
  Python 3.11, 3.12 and 3.13 across Linux and macOS.
- **Real data:** 11 evaluations from a fresh clone of the public `inspect_evals` repository, 30
  randomly sampled tasks each. Every finding was reproduced by calling the evaluation's own scorer
  directly, with Bohrin out of the loop. Two evaluations were refused with clear load errors (an
  uninstalled optional dependency, and a gated dataset).
- **Each safeguard against a false accusation was removed in turn** — the declined-submission
  triage, the swallowed-attempt check, and the list-target rule — and each removal failed its own
  test.
- `pip install 'bohrin[inspect]'` in a fresh virtual environment, then `bohrin audit` against a
  real public evaluation.
