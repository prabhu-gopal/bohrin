## TL;DR

1.0.1 fixes six defects a new user would hit on their first real audit — most
importantly a reproduction command that did not parse, and an infinite taskset
that hung with no output instead of honouring `--max-tasks`. No behaviour you
were relying on changes. Upgrade with `pip install --upgrade 'bohrin[verifiers]'`.

Every item was found by running the published 1.0.0 tool against real public
`verifiers` environments, not by the test suite. The definition of done was
right; the check that it had been met was missing. Each fix now has a test that
would have caught it.

## Upgrade impact

- **Breaking changes:** none
- **Action required:** none — `pip install --upgrade 'bohrin[verifiers]'`
- **New minimums:** none

## Highlights

- **The reproduction command on every finding now runs.** It printed
  `bohrin audit --task N --operator X` — neither flag existed, and the taskset
  path was missing — so the first thing a reader did with a finding was paste a
  command that exited with `unrecognized arguments`. Both flags are now
  implemented and honoured by both probes, the target is included and
  shell-quoted, and `--unsafe-local` is appended only when the audit actually
  ran without a boundary. A test feeds the printed command back through the
  parser so this cannot rot again.
- **`--max-tasks` actually bounds an audit now, and an infinite taskset is
  refused rather than hung.** The adapter read tasks through `Taskset.load()`
  (the hook that *builds* tasks) instead of iterating the taskset (which applies
  `head` / `shuffle` and the config-layer system prompt). Auditing an `INFINITE`
  taskset ran past ten minutes with no output and growing memory; the same run
  now completes in ~10 seconds at full coverage. The quieter cost was worse — a
  taskset configured with a system prompt was audited without it, which is not
  the task the customer runs.

## Fixed

- **A missing extra is reported before the isolation refusal.** Auditing a
  `verifiers` taskset without `bohrin[verifiers]` installed answered with "start
  docker" first, so the user fixed Docker, re-ran, and only then learned they
  needed the extra. The requirements check now runs before the isolation gate
  and imports nothing from the taskset.
- **Counts read as English.** `1 tasks`, `1 of 1 probes` and `1 task accept` all
  appeared in a single-task audit. Nouns and verbs now agree with the count.
- **Long payloads are elided with `…` instead of cut mid-word.** A payload
  truncated at exactly 96 characters read as a rendering bug, and the payload is
  the evidence.
- **A path that does not exist now says so**, instead of being answered with
  advice about installing extras.

## Known limitations

- **Recall on real environments is bounded by the six open operators, and that
  is visible in the numbers.** A sweep of six `verifiers` v1 environments found
  one real defect: `scratchpad` scores with `self.data.word in answer` while its
  own prompt contains `word="alpha"`, so echoing the prompt scores full marks on
  all 8 tasks without ever calling the tool — gap 50/100, confirmed
  independently through `verifiers` with Bohrin out of the loop. Of the other
  five, three measured clean at full coverage and two were declined rather than
  reported clean (`gsm8k` needs a runtime; `reverse_text`'s reference fails its
  own verifier). Two of those three "clean" results are a limit of the operators
  rather than a verdict on the grader: `glossary` grades by substring
  containment and `proposer_solver` by the last integer in the reply, both
  exploitable, but no model-free operator here constructs the payload that does
  it. **No false accusation was made in any run.**
