## TL;DR

Found by attacking 1.3.0 before trusting it to produce a published number. The fix that
matters: some environments store grader configuration where an answer normally goes, and
Bohrin denied that configuration, saw the grader accept the denial, and reported an exploit.
On one public environment that overstated the result by nearly double — **17 of 17 tasks
flagged, where 9 of 17 is defensible.** Also: seven command-line values that measure
nothing used to run and exit 0, which in CI reads as a pass, and now exit 2. Upgrade with
`pip install --upgrade`; a script is affected only if it passes one of those values.

## Upgrade impact

- **Breaking changes:** none — every refused value was already producing an audit that
  measured nothing
- **Action required:** only if a script passes one of the refused values. It will now exit
  2 instead of 0; that run was never measuring anything, so fix the value — most often by
  adding `--max-tasks N` beside an existing `--sample-seed`
- **New minimums:** none

## Highlights

- **No more exploits built on a grader's config** (#67). A JSON object in the answer field
  is grader state; findings resting on it become leads, and everything that needs no answer
  is still caught on the same task.
- **Values that measure nothing now fail** (#66), including `--sample-seed` without
  `--max-tasks`, which silently audited the whole taskset, and `--fail-on-gap 150`, a gate
  that could never close.
- **The README describes the tool you install** (#65, #66): both `verifiers` APIs, the
  blind spot that is actually open, and example output that matches a real run.

## Fixed

- **A JSON object in the answer field is no longer treated as the answer.** Some
  environments put grader configuration there instead of an answer — a constraint spec an
  instruction-following grader dispatches on, or a game's full state. Bohrin used to deny
  that "answer" (`The answer is not {"func_name": ...}.`), watch the grader accept it, and
  report an exploit. On one public environment, 8 of the 17 tasks it flagged rested on
  nothing else. Those candidates are now leads, not findings. What still counts on the same
  task is everything that needs no answer: a grader paying full marks for an empty reply,
  a refusal or an echoed prompt is still caught. `ground_truth_rejected` also stops
  reporting such a task as "rejecting its own answer". If your real answers are JSON
  objects, a denial of one is now a lead rather than an exploit; JSON arrays are unaffected.

- **A mistyped flag now fails instead of passing.** `--max-tasks 0`, `--repeats 0`,
  `--timeout 0`, a negative `--concurrency`, and a `--fail-on-gap` outside 0–100 each used
  to start an audit that measured nothing and exited 0, which in CI looks exactly like a
  clean result. `--fail-on-gap 150` was the quietest of them: a gate that can never close.
  All of them now exit 2 with a message naming the flag and what it accepts.
- **`--sample-seed` without `--max-tasks` is refused.** A seed chooses *which* tasks to
  take, so without a bound it has nothing to choose — and it was ignored without a word:
  asking for a sample of a 3270-task environment audited all 3270 and recorded no seed. It
  now tells you to add `--max-tasks N`.
- **The README's example is a real run again**, including the confidence intervals
  and the `rests on:` line it had been missing.

- **The README now says Bohrin reads both `verifiers` APIs.** It named only v1 tasksets and
  never mentioned `load_environment` — the entry point most published environments expose,
  and the one 1.2.0 added support for after recognising 0 of 109 environments without it. A
  maintainer with a `load_environment` environment would have read that page and concluded
  Bohrin could not audit their code. The page now names both, says which one the report
  header reports, and gives the `verifiers<0.3.2` pin for environments that resolve past
  upstream's removal of the legacy entry point.

- **The "honest edge of the open core" paragraph described a blind spot that 1.3.0 closed.**
  A grader reading only the last `\boxed{}` is now probed in that format, because the
  baseline learns it from the verifier's own acceptance of the declared answer. Both the
  README and `docs/05_ROBUSTNESS.md` still named it as the boundary that remains. They now
  name the real one: a task declaring no answer, where no baseline runs and so no format can
  be learned.

- **The operator count is seven, not six**, in the README and `docs/05_ROBUSTNESS.md`.
  `false_negation` was not counted.

- **Seven references to a version that was never released.** The September fixes were
  planned as 1.2.1 and shipped as 1.3.0; two of the stale references were in the public
  probe documentation.

- **`SECURITY.md` listed 1.1.x as the supported line**, and the open/closed boundary table
  in `docs/04_RELEASE.md` described the adapter row as v1-only.

## Verified

- `ruff check` · `ruff format --check` · `mypy --strict` · `pytest` — all clean on Python
  3.11, 3.12 and 3.13; **362 tests**, up from 326 at 1.3.0.
- **The false-accusation fix, on the environment that exposed it**, with the same 100
  tasks the sweep drew (`--max-tasks 100 --sample-seed 7`): `weak_oracle` went from 17 of
  17 tasks flagged to **9 of 17**; the 18 findings resting on the spec became leads, and the
  10 structural findings were unchanged; `ground_truth_rejected` went from 83 findings to
  **0**, now reported as not applicable with the reason. The 8 tasks that dropped out are
  the ones predicted from the earlier report before the change was written.
- **Scope measured across the whole sweep**, not assumed: of 57 environments, exactly two
  declare JSON objects in the answer field, and neither is an answer — one is a constraint
  spec, the other a game's full state.
- **Regression control** on an environment whose answers are real (20 sampled tasks):
  `false_negation` unchanged at 20 of 20, with no grounds withdrawn.
- **The refused values, end to end** on a real 3,270-task environment: `--sample-seed 7`,
  `--max-tasks 0`, `--fail-on-gap 150` and `--timeout 0` each exit 2 in under a second
  with a message naming the flag; a valid `--max-tasks 3 --sample-seed 7` run still works.
- **The README example** was re-run with the documented command against the environment
  it names, and now matches the real output.
